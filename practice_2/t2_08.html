Unicode и байты

15 минутЕрофеев А. И.

Научиться переводить символ в его номер Unicode и обратно, переводить строку в байты и объяснять, почему текст в чужой кодировке превращается в набор странных символов.

1. Символ и его номер

Теория

Python одинаково работает и с латиницей, и с кириллицей, хотя компьютер умеет хранить только числа. Значит, каждой букве кто-то присвоил номер. Этим занимается стандарт Unicode, общий для всего мира.

Кодовая точка — номер символа в стандарте Unicode.

Строка Python состоит из символов Unicode, поэтому ей все равно, на каком языке текст. Функция ord() возвращает номер символа: ord("П") дает 1055. Функция chr() делает обратное и возвращает символ по номеру: chr(1055) возвращает букву П.

Номера объясняют сравнение строк (страница 03): у заглавных латинских букв номера от 65 до 90, у строчных от 97 до 122, поэтому "Zebra" < "apple". Латинские буквы идут подряд, поэтому к номеру буквы можно прибавить число и получить букву дальше по алфавиту.

Кодовые точки лежат в диапазоне от 0 до 1 114 111. В документации их записывают шестнадцатеричным числом с приставкой U+: латинская A имеет номер U+0041, то есть 65, буква П номер U+041F, то есть 1055.

Функция ord() принимает ровно один символ. Строка из двух символов дает ошибку TypeError, как и пустая строка.

Пример

Номера символов

codepoints.py
print(ord("A"), ord("a"))  # → 65 97
print(ord("П"))            # → 1055
print(chr(1055))           # → П
print(chr(ord("A") + 2))   # → C
print("Zebra" < "apple")   # → True
Вывод
65 97
1055
П
C
True
  1. Строка 1: у заглавной и строчной A разные номера.
  2. Строки 2–3: ord() и chr() переводят символ в номер и обратно.
  3. Строка 4: номер A плюс 2 дает номер буквы на два места дальше.
  4. Строка 5: 90 меньше 97, поэтому Z стоит раньше a.

2. Байты и кодировка

Теория

В файл и в сеть текст уходит байтами. Правило, по которому символы переводят в байты, называют кодировкой. Самая распространенная кодировка UTF-8 записывает латинские буквы, цифры, пробел и знаки с клавиатуры одним байтом, русскую букву двумя.

Метод encode("utf-8") переводит строку в байты, тип bytes. Метод decode("utf-8") переводит байты обратно в строку. Функция len() у строки считает символы, а у bytes считает байты.

Если байты расшифровать не той кодировкой, текст превращается в набор странных символов. Данные при этом целы: их нужно прочитать в той кодировке, в которой их записали.

Значение типа bytes Python показывает с буквой b перед кавычками. Байты вне латиницы записаны через \x и две шестнадцатеричные цифры: b'\xd0\x9f' — это два байта буквы П.

UTF-8 записывает символ одним, двумя, тремя или четырьмя байтами, в зависимости от его номера. Символы с номерами до 127, то есть латиница, цифры и знаки клавиатуры, занимают один байт, русские буквы два, знак евро три. Старые кодировки, например cp1251 в Windows, отводят каждому символу один байт и поэтому умеют записать только часть символов Unicode. Когда появятся файлы, кодировку при их открытии будут указывать явно.

Пример

Символы и байты

bytes_demo.py
text = "Проба S12"
data = text.encode("utf-8")
print(len(text))              # → 9
print(type(data))             # → <class 'bytes'>
print(len(data))              # → 14
print(data[:4])               # → b'\xd0\x9f\xd1\x80'
print(data.decode("utf-8"))   # → Проба S12
print(data.decode("cp1251"))  # → РџСЂРѕР±Р° S12
Вывод
9
<class 'bytes'>
14
b'\xd0\x9f\xd1\x80'
Проба S12
РџСЂРѕР±Р° S12
  1. Строка 3: девять символов, считая пробел.
  2. Строки 4–5: в байтах 14, потому что каждая из пяти русских букв заняла два байта, а остальные четыре символа по одному.
  3. Строка 6: первые четыре байта, это буквы П и р.
  4. Строка 7: расшифровка той же кодировкой вернула текст.
  5. Строка 8: те же байты прочитаны как cp1251, и русская часть превратилась в набор странных символов; латиница не пострадала.
Практика

Посчитайте, сколько байтов в UTF-8 занимают слово ген и знак евро €. Сравните с числом символов.

Упражнение 2.8.1. Качество прочтения

Условие задачи

В формате FASTQ качество каждого прочитанного нуклеотида записано одним символом. В распространенной схеме Sanger оценка качества по шкале Phred равна номеру символа минус 33: символу J с номером 74 соответствует оценка 41. Дана строка качества прочтения. Выходные данные

Две строки: оценка качества первого нуклеотида и оценка качества последнего.

Качество показывает уверенность в каждом нуклеотиде; в FASTQ его записывают символом, а оценку Phred вычисляют из номера символа. Первый нуклеотид стоит по индексу 0, последний — по индексу -1.

Основные определения

  • Прочтение — участок ДНК, который секвенатор прочитал за один раз.

  3. Оценка — номер символа минус 33: ord(quality[0]) - 33 и ord(quality[-1]) - 33.

Упражнение 2.8.1. Русские буквы в тексте

Условие задачи

В комментарии к записи смешаны латиница и кириллица. Посчитайте, сколько в нем русских букв. Циклы и ветвления для этого не нужны.

Входные данные

Одна строка длиной от 1 до 200: латинские и русские буквы, цифры, пробелы и знаки препинания с клавиатуры (. , : ; ! ? - ( )).

Выходные данные

Целое число: количество русских букв в строке.

Вывод 16

Длина строки в символах 24, а в байтах UTF-8 40; каждая русская буква добавляет по лишнему байту, поэтому русских букв 40 − 24 = 16.

Контекст

В кодировке UTF-8 латинская буква занимает один байт, а русская — два. Поэтому число русских букв — это разница между длиной строки в байтах и длиной в символах.

Основные определения

  • Кодировка — способ записи символов байтами.
  • UTF-8 — кодировка, в которой латинская буква занимает один байт, а русская — два.
  • Байт — единица хранения данных, одно число от 0 до 255.
  • len() — возвращает число символов в строке.
  • Метод encode() — переводит строку в байты в заданной кодировке.
Подсказка
  1. Прочитайте строку: text = input().
  2. Длина строки в байтах: len(text.encode("utf-8")).
  3. Каждая русская буква дает лишний байт, поэтому их число — разность длин: len(text.encode("utf-8")) - len(text).
  4. Выведите результат; сверьтесь с примером: в Ген BRCA1 кодирует белок 16 русских букв, а в GATTACA — ни одной.

Задача со звездочкой 2.8. Символ качества в другой схеме

Условие задачи

Выходные данные

Задача со звездочкой 2.8. Испорченная кодировка

Условие задачи

Подсказка

  4. Выведите текст: перекодируйте его методом encode("cp1251"), затем примените decode("utf-8"); сверьтесь с примером: РєСЂРѕРІСЊ S12 превращается в кровь S12.

Задача со звездочкой 2.8. Верные концы прочтения

Условие задачи

В формате FASTQ качество каждого нуклеотида записано символом; в схеме Sanger оценка качества quality_score по шкале Phred равна номеру символа минус 33. Оценка связана с вероятностью ошибки error_probability формулой error_probability = 10−quality_score/10: оценке 20 соответствует ошибка с вероятностью 0,01 (источник: Ewing, Green, 1998). Дана строка качества прочтения. Найдите вероятность того, что первый и последний нуклеотиды прочитаны верно. Ошибки в разных позициях считайте независимыми: искомая вероятность равна произведению (1 − p_first) · (1 − p_last).

Входные данные

Одна строка качества длиной от 2 до 100 из символов с номерами от 33 до 126.

Выходные данные

Вероятность с четырьмя знаками после точки.

Пример

Разберем пример

Ввод 5FFJJ+
→
Вывод 0.8910

Контекст

Оценка Phred 20 означает одну ошибку на сто нуклеотидов, и вероятность верного прочтения одного нуклеотида равна 1 − error_probability. Вероятность двух независимых верных прочтений перемножается.

Основные определения

  • Прочтение — участок ДНК, который секвенатор прочитал за один раз.
  • Шкала Phred — оценка качества quality_score: чем больше, тем увереннее прочитан нуклеотид.
  • Вероятность ошибки — вероятность error_probability того, что нуклеотид прочитан неверно; error_probability = 10^(−quality_score/10).
  • Независимые события — события, вероятность которых не зависит друг от друга; их вероятности перемножаются.
Подсказка
  1. Прочитайте строку качества: quality = input().
  2. Оценки концов: q_first = ord(quality[0]) - 33, q_last = ord(quality[-1]) - 33.
  3. Вероятности ошибки: p_first = 10 ** (-q_first / 10), так же для последнего.
  4. Искомая вероятность — f"{(1 - p_first) * (1 - p_last):.4f}"; сверьтесь с примером: 5FFJJ+ дает 0.8910.
