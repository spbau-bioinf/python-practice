Операции со строками

30 минутЕрофеев А. И.

Научиться склеивать и повторять строки, проверять вхождение подстроки оператором in, сравнивать строки и собирать новую строку вместо изменения старой.

1. Склеить, повторить, найти

Теория

Из строк постоянно что-то собирают: идентификатор из префикса и номера, строку отчета из полей, линию для оформления вывода. Один из самых частых вопросов к последовательности: есть ли в ней нужный мотив, например сайт рестрикции GAATTC, который узнает фермент EcoRI.

Оператор + склеивает строки и ничего не вставляет между ними: пробел или разделитель добавляют сами. Из "37" + "42" получается "3742", а не 79: строки из цифр не складываются как числа. Оператор * повторяет строку целое число раз: "-" * 20 рисует линию из 20 дефисов. Оба оператора вы видели на странице 05 первой практики.

Подстрока — участок строки из идущих подряд символов.

Оператор in проверяет, входит ли одна строка в другую как подстрока, и дает True или False. Слева пишут то, что ищут, справа то, где ищут. Регистр важен: "dna" in "DNA sequence" дает False.

От перестановки слагаемых результат меняется: "AT" + "GC" и "GC" + "AT" разные строки. Умножать можно с любой стороны: "AT" * 3 и 3 * "AT" дают одно и то же. Умножение на 0 или на отрицательное число дает пустую строку.

Строку склеивают только со строкой. Число сначала превращают в строку функцией str() (страница 05 первой практики). Пустая строка считается подстрокой любой строки: "" in "ACGT" дает True.

Пример

Операторы +, * и in

number = "042"
print(prefix + "_" + number)  # → gene_042
print("37" + "42")            # → 3742
print("=" * 12)               # → ============
seq = "TTGAATTCAG"
print("GAATTC" in seq)        # → True
print("gaattc" in seq)        # → False
Вывод
gene_042
3742
============
True
False
  1. Строка 3: три строки склеены подряд, разделитель _ добавлен явно.
  2. Строка 4: строки из цифр склеиваются, а не складываются.
  3. Строка 5: линия из 12 знаков равенства.
  4. Строки 7–8: сайт GAATTC в последовательности есть, а строчными буквами он не найден, потому что in учитывает регистр.

Типичная ошибка: строка плюс число

Неверно: TypeError
number = 12
print("S" + number)
Сообщение об ошибке
Traceback (most recent call last):
  File "concat.py", line 2, in <module>
    print("S" + number)
          ~~~~^~~~~~~~

Верно
number = 12

Python не угадывает, что нужно: склеить или сложить. Сообщение прямо говорит, что к строке можно приклеить только строку, поэтому число превращают в строку функцией str().

2. Сравнение строк

Теория

Сравнивать строки приходится постоянно: совпадает ли идентификатор, та ли это последовательность, в каком порядке расставить названия. У Python на этот счет свои правила, и одно из них расходится со словарем.

Операторы == и != сравнивают строки символ за символом. Строки равны, только если совпадают все символы, включая регистр и пробелы: "ACGT" == "acgt" дает False, и "ACGT " == "ACGT" тоже дает False.

Операторы <, >, <=, >= сравнивают строки как в словаре: сначала первые символы, при равенстве вторые, и так далее. "apple" < "banana" дает True. Но порядок символов у Python свой: все заглавные латинские буквы стоят раньше любой строчной, поэтому "Zebra" < "apple" тоже дает True.

Строки сравниваются по номерам символов в таблице Unicode. У заглавных латинских букв номера от 65 до 90, у строчных от 97 до 122. Номер буквы Z равен 90, номер буквы a равен 97, и первые же символы решают исход сравнения. Номера символов разобраны на странице 08.

Если одна строка служит началом другой, меньше та, что короче: "AT" < "ATG" дает True. Строки из цифр сравниваются как текст, а не как числа: "10" < "9" дает True, потому что символ 1 стоит раньше символа 9.

Чтобы сравнивать без учета регистра, обе строки сначала приводят к одному регистру методом lower() или upper() (страница 04). Лишний пробел на краю строки на экране не виден, а сравнение уже ложно; такие пробелы часто приходят с вводом, их убирает метод strip() (страница 05).

print("ACGT " == "ACGT")   # → False
print("apple" < "banana")  # → True

print("AT" < "ATG")        # → True
Вывод

False

True
True

  2. Строка 3: словарный порядок, a раньше b.
  3. Строка 4: заглавная Z стоит раньше строчной a.

3. Строку нельзя изменить

Теория

Заменить нуклеотид приходится часто: внести точечную мутацию, исправить ошибку прочтения, подставить другой кодон. В строке это не делается «на месте».

Строка неизменяема: заменить в ней символ нельзя. Присваивание seq[2] = "A" завершается ошибкой TypeError: объект str не поддерживает присваивание элементу.

Вместо изменения собирают новую строку из кусков старой: seq[:2] + "A" + seq[3:] дает новую строку с другим третьим символом, а исходная строка остается прежней. Чтобы имя указывало на новую строку, результат присваивают: seq = seq[:2] + "A" + seq[3:]. Так же устроены все методы строк (страница 04): они не меняют строку, а возвращают новую.

После присваивания seq = seq[:2] + "A" + seq[3:] старая строка остается в памяти прежней, но имя seq на нее больше не указывает. Когда на объект не указывает ни одно имя, Python сам освобождает занятую им память. Как имена связаны с объектами, разобрано на странице 04 первой практики.

Неизменяемы и другие типы, которые вы уже знаете: int, float, bool, Decimal. Изменяемые типы, например списки, появятся позже.

Замену удобно проверять длиной: при замене одного символа длина строки не меняется. Если строка стала длиннее, символ не заменен, а вставлен.

Пример

Изменить символ нельзя

immutable.py
seq = "ATGCGATCG"
print(seq[2])  # → G
seq[2] = "A"
Вывод
G
Сообщение об ошибке
Traceback (most recent call last):
  File "immutable.py", line 3, in <module>
    seq[2] = "A"
    ~~~^^^
TypeError: 'str' object does not support item assignment
  1. Строка 2: прочитать символ по индексу можно.
  2. Строка 3: записать символ по индексу нельзя, программа завершается ошибкой.

Замена нуклеотида

mutation.py
seq = "ATGCGATCG"
mutant = seq[:2] + "A" + seq[3:]
print(mutant)                 # → ATACGATCG
print(seq)                    # → ATGCGATCG
print(len(mutant), len(seq))  # → 9 9
seq = mutant
print(seq)                    # → ATACGATCG
Вывод
ATACGATCG
ATGCGATCG
9 9
ATACGATCG
  1. Исходная последовательность.
  2. Новая строка: два первых символа, новая буква, все начиная с четвертого символа.
  3. В новой строке третий нуклеотид заменен на A.
  4. Исходная строка не изменилась.
  5. Проверка длиной: символ заменен, а не вставлен.
  6. Имя seq теперь указывает на новую строку.
  7. Печатается новая строка.

Типичная ошибка: вставка вместо замены

Неверно: строка стала длиннее
seq = "ATGCGATCG"
print(seq[:3] + "A" + seq[3:])  # → ATGACGATCG
Вывод
ATGACGATCG
Верно
seq = "ATGCGATCG"
print(seq[:2] + "A" + seq[3:])  # → ATACGATCG
Вывод
ATACGATCG

Срез seq[:3] уже содержит третий символ, поэтому новая буква встала после него, и последовательность выросла на один нуклеотид. Срезы по бокам от заменяемого символа должны заканчиваться на нем и начинаться сразу после него: seq[:2] и seq[3:].
