Практика 3›Истинность и значение по умолчанию

Истинность значений

20 минутЕрофеев А. И.

Научиться писать в условии саму строку или число вместо сравнения, подставлять значение по умолчанию оператором or и замечать случаи, где ноль настоящее значение.

1. Ложные и истинные значения

Теория

На странице 02 запись code == "S" or "W" вела себя странно: строка "W" без сравнения работала как условие. Дело в том, что в условии Python принимает любое значение, а не только True и False. Это удобно, если знать правило.

В условии if, в and, or и not может стоять любое значение. Python сам решает, считать ли его истиной. Ложными считаются None, False, ноль любого числового типа (0, 0.0) и пустая строка "", а также пустые коллекции, например пустой список (тема 5 «Списки и кортежи»). Все остальные встроенные значения истинны.

Ложна только пустая строка. Строки "0", " " и "False" не пустые и потому истинны, хотя выглядят как «ничего» или «ложь». Узнать, истинно ли значение, можно функцией bool(): она возвращает True или False.

ТипЛожные значенияПримеры истинных
boolFalseTrue
int, float0, 0.01, -1, 0.001
str"""0", " ", "False"
NoneTypeNoneнет

Истинность значения — то, чем значение считается в условии: истиной или ложью. Ложные значения называют также falsy, истинные truthy.

Пример

Что ложно

Предскажите вывод каждой строки.

truth.py
print(bool(0.0))      # → False
print(bool("0"))      # → True
print(bool(" "))      # → True
print(bool("False"))  # → True
print(bool(""))       # → False
print(bool(-1))       # → True
Вывод
False
True
True
True
False
True
  1. Строки 1 и 5: ноль и пустая строка ложны.
  2. Строки 2–4: непустые строки истинны, что бы в них ни было написано.
  3. Строка 6: отрицательное число не ноль, поэтому истинно.
Практика

Проверьте bool() для строки, которую возвращает input(), если нажать Enter, ничего не набрав. Затем для числа 0.0001.

try_bool.py
print(bool(0))       # → False
print(bool("ACGT"))  # → True
Вывод

True

2. Истинность в условиях

Теория

Проверка «пусто или нет» встречается постоянно: пустая строка из ввода, пустое поле, пустая последовательность. Истинность позволяет записать ее короче и ближе к смыслу.

Вместо if len(seq) > 0: пишут if seq:, вместо if len(seq) == 0: пишут if not seq:. Писать if bool(seq): незачем: приведение к логическому значению в if уже есть.

Логические значения не сравнивают с True и False через ==: пишут if ok:, а не if ok == True:. Сравнение с True еще и опасно: 2 == True дает False, хотя число 2 в условии истинно.

Короткая проверка не подходит там, где ноль или пустая строка — настоящее значение. GC-состав 0.0 означает последовательность из одних A и T, а не отсутствие результата. В таких случаях нужно явное сравнение; как отличать «нет значения» от нуля, разобрано на странице 07.

Пример

Пустой ввод

Программа ждет ввода. Пользователь нажимает Enter, ничего не набрав.

empty_input.py
seq = input()
if seq:
    print("получено нуклеотидов:", len(seq))
else:
    print("последовательность не введена")  # → последовательность не введена
Вывод

последовательность не введена

Функция input() вернула пустую строку, она ложна, и выполнилась ветвь else. Условие if seq: читается как «если последовательность есть».

Типичная ошибка: сравнение с True

Неверно: ветвь не выполняется
n_count = "ATNNGC".count("N")
if n_count == True:
    print("есть неизвестные нуклеотиды")
print("проверка окончена")  # → проверка окончена
Вывод
проверка окончена
Верно
n_count = "ATNNGC".count("N")
if n_count:
    print("есть неизвестные нуклеотиды")  # → есть неизвестные нуклеотиды
print("проверка окончена")                # → проверка окончена
Вывод
есть неизвестные нуклеотиды
проверка окончена

Букв N две. Число 2 истинно, но True равно 1 (страница 01), и 2 == True ложно. С одной буквой N ошибка не проявилась бы, поэтому ее легко пропустить при проверке.

Подробнее: почему True равно единице

Тип bool устроен как разновидность int: True хранится как 1, False как 0. Поэтому 1 == True истинно, а любое другое ненулевое число True не равно. Документ PEP 285, который ввел тип bool, называет правильной запись if x:, а примером 6 == True == 7 объясняет, почему True не может быть равно каждому истинному значению: тогда из этой цепочки следовало бы 6 == 7. Руководство по стилю PEP 8 прямо называет сравнение с True через == ошибкой.

Практика

Перепишите условие короче, через истинность строки, и проверьте программу на пустой строке и на строке "GATTACA".

comment = ""
if len(comment) == 0:
    print("комментария нет")  # → комментария нет
else:
    print("комментарий:", comment)
Вывод

3. or и and возвращают значение

Теория

Теперь понятно, почему на странице 02 print(code == "S" or "W") напечатало букву. Операторы and и or не превращают результат в True или False: они возвращают одно из своих значений.

x or y возвращает x, если x истинно, иначе y. x and y возвращает x, если x ложно, иначе y. Если оба значения логические, результат тот же, что в таблице истинности. Если нет, результатом будет одно из этих значений, например строка или число. Поэтому code == "S" or "W" вернуло строку "W".

На этом строится значение по умолчанию: name = seq_id or "без имени" дает идентификатор, а если он пустой, запасную строку. Ограничение то же, что у проверки истинности: если ноль — настоящее значение, x or 5 заменит и его. Сложную логику на and и or не строят: для нее есть if.

Пример

Какое значение вернул оператор

Предскажите вывод.

or_and.py
seq_id = ""
name = seq_id or "без имени"
print(name)           # → без имени
print("ACGT" or "N")  # → ACGT
print(0 and 5)        # → 0
print(0 or 5)         # → 5
Вывод
без имени
ACGT
0
5
  1. Строка 2: пустая строка ложна, or возвращает правую часть.
  2. Строка 4: левая часть истинна, и or возвращает ее, правую даже не вычисляя (страница 03).
  3. Строка 5: левая часть and ложна, она и возвращается.
  4. Строка 6: левая часть or ложна, возвращается правая.

Ноль заменен значением по умолчанию

zero_default.py
gc = 0.0
shown = gc or 50.0
print(shown)  # → 50.0
Вывод
50.0

GC-состав 0.0 настоящий результат, но он ложен, и or подставил запасное значение. Здесь нужен if с явной проверкой, а не or.
