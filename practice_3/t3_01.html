bool и сравнения

30 минутЕрофеев А. И.

Научиться получать ответ «да» или «нет» сравнением, сравнивать числа из ввода и считать истинные ответы сложением логических значений.

1. Логический тип

Теория

Любое решение программы начинается с ответа «да» или «нет»: начинается ли строка с >, длиннее ли последовательность 100 нуклеотидов, превышает ли концентрация порог. Записать такой ответ строкой «да» неудобно: строку можно написать с опечаткой, а на вопрос «да или нет» ответов ровно два. Поэтому у ответа есть свой тип данных.

Ответ «да» или «нет» в программе имеет тип bool. У этого типа ровно два значения: True (истина) и False (ложь). Тип bool встречался на странице 05 первой практики; в этой практике он становится главным.

Логическое значение — значение типа bool, то есть True или False.

True и False пишутся с прописной буквы и без кавычек. "True" в кавычках уже строка из четырех букв, а слово true со строчной буквы Python не знает. В арифметике True ведет себя как 1, а False как 0: True + True дает 2. Поэтому сумма нескольких логических значений равна числу истинных среди них.

Тип bool появился в Python 2.3 (предложение PEP 285). До этого вместо истины и лжи писали 1 и 0, и новый тип сохранил это родство: bool устроен как разновидность целого типа int. Поэтому сумма логических значений получается целым числом.

Пример

Значения типа bool

bool_type.py
answer = True
print(answer)               # → True
print(type(answer))         # → <class 'bool'>
print(type("True"))         # → <class 'str'>
print(True + True + False)  # → 2
Вывод
True
<class 'bool'>
<class 'str'>
2
  1. Строка 1: переменная answer связана с логическим значением True.
  2. Строки 3–4: True без кавычек имеет тип bool, а "True" в кавычках имеет тип str.
  3. Строка 5: два истинных значения и одно ложное в сумме дают 2.

Типичная ошибка: true со строчной буквы

Неверно: NameError
done = true
print(done)
Сообщение об ошибке
Traceback (most recent call last):
  File "done.py", line 1, in <module>
    done = true
           ^^^^
NameError: name 'true' is not defined. Did you mean: 'True'?
Верно

Вывод

Для Python true обычное имя переменной, а такой переменной в программе нет. В других языках (JavaScript, Java) логические значения пишут со строчной буквы, поэтому эта ошибка часто встречается у тех, кто на них программировал. Python сам подсказывает правильное написание.

2. Операторы сравнения

Теория

Чаще всего логическое значение не пишут в коде готовым, а получают сравнением: длина последовательности сравнивается с порогом, pH с семеркой, введенный номер с номером в журнале. Сравнение похоже на вопрос, который программа задает данным.

Сравнение двух значений дает True или False. Результат можно напечатать, связать с переменной и использовать в выражении, как любое значение. Операторов сравнения шесть:

ОператорСмыслПримерРезультат
<меньше3 < 5True
>больше3 > 5False
<=меньше или равно5 <= 5True
>=больше или равно4 >= 5False
==равно2 == 2.0True
!=не равно3 != 3False

Один знак = присваивает значение, два знака == сравнивают. Операторов =< и => нет: знак равенства в двойных операторах всегда стоит вторым. Целое и вещественное число сравниваются по значению, поэтому 2 == 2.0 дает True.

Функция input() возвращает строку. Число из ввода перед сравнением превращают функцией int() или float(), как перед вычислениями (страница 09 первой практики).

Результат любого сравнения имеет тип bool, даже если сравнивались числа или строки.

В Python есть еще четыре оператора сравнения: is и is not (страница 07), in и not in (страница 03). Они отвечают на другие вопросы: тот же ли это объект и входит ли значение в строку как подстрока.

Пример

Длина и порог

Программа ждет ввода. Пользователь набирает 120 и нажимает Enter.

length_check.py
length = int(input())
print(length >= 100)  # → True
print(length == 100)  # → False
print(length != 100)  # → True
Вывод
120
True
False
True
  1. Строка 1: строка из ввода превращена в целое число 120.
  2. Строка 2: 120 больше 100, поэтому «больше или равно» дает True.
  3. Строки 3–4: 120 не равно 100, поэтому == дает False, а != дает True.

Граница порога

Значение, равное порогу, отличает строгий знак от нестрогого. Предскажите вывод, прежде чем открыть его.

border.py
gc = 50.0
print(gc > 50)   # → False
print(gc >= 50)  # → True
print(gc == 50)  # → True
Вывод
False
True
True
  1. Строка 2: строгий знак > не пропускает значение, равное порогу.
  2. Строка 3: нестрогий знак >= его пропускает.
  3. Строка 4: вещественное 50.0 и целое 50 равны по значению.

Результат сравнения в переменной

is_long.py
min_len = 10
seq = "ATGCGTACGT"
is_long = len(seq) >= min_len
print(is_long)        # → True
print(type(is_long))  # → <class 'bool'>
Вывод
True
<class 'bool'>
  1. Строка 3: сначала вычисляется сравнение 10 >= 10, затем его результат связывается с именем is_long. Знак = здесь присваивает, знак >= сравнивает.
  2. Строка 5: в переменной хранится логическое значение, его тип bool.

Типичная ошибка: один знак равенства вместо двух

Неверно: TypeError
length = 120
print(length = 100)
Сообщение об ошибке
Traceback (most recent call last):
  File "equal.py", line 2, in <module>
    print(length = 100)
TypeError: print() got an unexpected keyword argument 'length'
Верно
length = 120
print(length == 100)  # → False
Вывод
False

Внутри скобок print() запись length = 100 Python понимает как именованный аргумент функции, вроде sep=" ", и сообщает, что такого аргумента у print() нет. Текст ошибки не говорит о сравнении, поэтому причину приходится узнавать по знаку =.

Подробнее: вещественные числа и ==

Сравнение 0.1 + 0.2 == 0.3 дает False: сумма хранится с погрешностью и равна 0.30000000000000004. Результаты вычислений с вещественными числами сравнивают с допуском функцией math.isclose() (страница 07 первой практики). Сравнения < и > с порогом погрешность почти не затрагивает, если значение не лежит на самой границе.

3. Строки и разные типы

Теория

Номера проб, идентификаторы и названия генов приходят в программу текстом, а сравнивать их нужно по смыслу: номер 9 меньше номера 10, хотя строка "9" больше строки "10". Чтобы сравнение отвечало на тот вопрос, который вы задали, нужно знать, как Python сравнивает строки и значения разных типов.

Строки сравниваются теми же операторами. Как это устроено, разобрано на странице 03 второй практики: символ за символом, по номерам символов в Unicode, с учетом регистра. Все прописные латинские буквы стоят раньше строчных, поэтому "a" < "B" дает False. Чтобы сравнивать без учета регистра, обе строки приводят к одному регистру методом lower() или upper().

Число и строка никогда не равны: 5 == "5" дает False, хотя на экране оба значения выглядят как 5. Сравнить их на «больше» или «меньше» нельзя: 5 < "5" останавливает программу с ошибкой TypeError.

Поэтому то, что по смыслу число, сравнивают как число. Строки из цифр сравниваются как текст: "10" < "9" дает True, потому что символ 1 стоит раньше символа 9. Ведущие нули строку меняют, а число нет: "08" == "8" дает False, а int("08") == 8 дает True.

СимволНомер ord()Что из этого следует
"0"–"9"48–57цифры раньше любых букв
"A"–"Z"65–90прописные раньше строчных
"a"–"z"97–122"a" > "Z"

Функция ord() (страница 08 второй практики) показывает номер символа, и по номерам видно, почему "a" < "B" ложно: номер строчной a равен 97, а номер прописной B равен 66.

Типичная ошибка: строка из ввода не превращена в число

Неверно: TypeError
reads = "120"
print(reads > 100)
Сообщение об ошибке
Traceback (most recent call last):
  File "reads.py", line 2, in <module>
    print(reads > 100)
          ^^^^^^^^^^^
TypeError: '>' not supported between instances of 'str' and 'int'
Верно

print(reads > 100)  # → True
Вывод

Строка "120" здесь стоит на месте того, что вернула бы функция input(). Сообщение называет оба типа: слева str, справа int. Если же сравнить две строки из ввода без int(), ошибки не будет, но "120" > "99" даст False: такую ошибку заметить труднее.

Подробнее: почему == для разных типов не дает ошибку

На равенство можно проверить любые два объекта: если Python не знает, как их сравнить, он считает их неравными. Для порядка такого ответа по умолчанию нет, поэтому < и > для числа и строки дают TypeError. Числа разных типов (int, float, bool) сравниваются между собой по значению, поэтому True == 1 тоже дает True.

Выберите свой уровень во вкладках любого упражнения: здесь останутся только имена файлов вашего уровня и появится структура папок.
