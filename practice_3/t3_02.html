Логические операторы

30 минутЕрофеев А. И.

Научиться собирать сложное условие из простых операторами and, or, not, расставлять скобки по приоритету и записывать сравнение полностью в каждой части условия.

1. and, or, not

Теория

Одного сравнения часто мало. Последовательность годится для анализа, если она длиннее 100 нуклеотидов и в ней нет неизвестных нуклеотидов N. Показатель анализа требует внимания, если он ниже нормы или выше нормы. Это два простых условия, соединенных словами «и», «или». В Python для этого есть логические операторы.

Логические операторы соединяют условия так же, как союзы в речи. a and b истинно, только если истинны обе части. a or b истинно, если истинна хотя бы одна часть. not a меняет значение на противоположное. Части условия удобно сначала вычислить и связать с переменными: тогда условие читается как фраза.

aba and ba or bnot a
TrueTrueTrueTrueFalse
TrueFalseFalseTrueFalse
FalseTrueFalseTrueTrue
FalseFalseFalseFalseTrue

Логический оператор — оператор, который соединяет условия или меняет условие на противоположное: and (и), or (или), not (не).

Имя переменной с логическим значением удобно читать как вопрос: is_long («длинная ли?»), has_n («есть ли N?»). Тогда условие is_long and not has_n читается как фраза: длинная и без N.

В речи «или» иногда значит «одно из двух, но не оба»: «чай или кофе». В Python or всегда включающее: True or True дает True. Если нужно «ровно одно из двух», условие записывают иначе.

Пример

Длина и неизвестные нуклеотиды

compound.py
seq = "ATGCGTTAGCAN"
is_long = len(seq) >= 10
has_n = seq.count("N") > 0
print(is_long and not has_n)  # → False
print(is_long or has_n)       # → True
print(not has_n)              # → False
Вывод
False
True
False
  1. Строки 2–3: два простых условия вычислены заранее. Последовательность достаточно длинная (is_long равно True), но в ней есть N (has_n равно True).
  2. Строка 4: not has_n ложно, а для and одной ложной части достаточно, чтобы все условие стало ложным.
  3. Строка 5: для or достаточно одной истинной части.
  4. Строка 6: not переворачивает True в False: утверждение «N в последовательности нет» ложно.

Температура инкубации

Культуру клеток держат при температуре от 36 до 38 градусов включительно. Предскажите, что выведет каждая строка.

incubator.py
low = 36.0
high = 38.0
temp = 38.4
ok = temp >= low and temp <= high
print(ok)      # → False
print(not ok)  # → True
Вывод
False
True
  1. Строка 4: «в пределах» означает не ниже нижней границы и одновременно не выше верхней, поэтому части соединены and. Температура 38,4 выше верхней границы, вторая часть ложна, и все условие ложно.
  2. Строка 6: not дает противоположный ответ: температура вышла за пределы.

Типичная ошибка: вторая часть без левого операнда

Неверно: SyntaxError
x = 5
print(x > 0 and < 10)
Сообщение об ошибке
  File "range.py", line 2
    print(x > 0 and < 10)
                    ^
SyntaxError: invalid syntax
Верно
x = 5
print(x > 0 and x < 10)  # → True
Вывод
True

По-русски можно сказать «больше нуля и меньше десяти», а в Python каждая часть and должна быть полным условием. Стрелка в сообщении показывает на знак <, у которого нет левого операнда.

2. Приоритет операторов

Теория

В условии с несколькими операторами важно, какой из них связывает сильнее, как в арифметике умножение связывает сильнее сложения: 2 + 3 * 4 читается как 2 + (3 * 4). Ошибка в группировке не вызывает сообщения: программа просто проверяет не то, что вы имели в виду.

Приоритет операторов определяет, как Python расставляет невидимые скобки в сложном условии. Сильнее всех связывают арифметика и сравнения, слабее not, еще слабее and, слабее всех or. Поэтому not x > 5 читается как not (x > 5), а a or b and c как a or (b and c).

Если в условии есть и and, и or, ставьте скобки, даже когда группировка и так верная. Скобки группируют части явно и показывают читателю, что вы имели в виду.

ПриоритетОператорыПримерКак читается
1скобки(a or b) and ca or b одной группой
2арифметикаx + 1 > y(x + 1) > y
3сравнения, innot x == ynot (x == y)
4notnot a and b(not a) and b
5anda or b and ca or (b and c)
6ora and b or c(a and b) or c

Условие not 3 > 5 or 2 == 2 and False получает скобки так (сворачивание показывает группировку; вычисляет Python слева направо, с сокращенным вычислением со страницы 03):

  1. not 3 > 5 or 2 == 2 and Falseисходное условие
  2. not False or True and Falseсравнения связывают сильнее всех
  3. True or True and Falseзатем not
  4. True or Falseзатем and
  5. Trueпоследним or
Пример

Скобки меняют ответ

Предскажите вывод, прежде чем открыть его.

priority.py
print(True or False and False)    # → True
print((True or False) and False)  # → False
print(not 5 > 3)                  # → False
Вывод
True
False
False
  1. Строка 1: and связывает сильнее, поэтому условие читается как True or (False and False). Левая часть or истинна, и правая даже не вычисляется (страница 03).
  2. Строка 2: скобки объединяют True or False в одну группу, и ответ меняется.
  3. Строка 3: сравнение связывает сильнее not: 5 > 3 истинно, not делает его ложным.
Подробнее: & и | вместо and и or

В Python есть операторы & и |, похожие на «и» и «или» из других языков. Это поразрядные операции над целыми числами, и приоритет у них выше, чем у сравнений. Поэтому при a = 10 выражение a <= 10 & 1 < a дает False: сначала вычисляется 10 & 1. С and то же условие дает True. В условиях пишите and, or и not. С & и | вы встретитесь в библиотеке pandas, там у них свой смысл.

Практика

print(not 7 == 7)              # → False
Вывод

False

3. Сравнение в каждой части

Теория

По-русски мы говорим «буква равна A или C» и не повторяем «буква равна». В Python такая сокращенная запись не дает ошибки, но проверяет совсем другое. Это одна из самых частых ошибок в условиях.

Каждая часть or и and вычисляется отдельно. В записи base == "A" or "C" левая часть base == "A", а правая просто строка "C", без сравнения. Непустая строка в условии считается истиной, поэтому такое условие выполняется при любой букве. Что именно возвращает or в этом случае, разобрано на странице 06.

Сравнение пишется полностью в каждой части: base == "A" or base == "C".

Похожая запись с != ошибается иначе. x != "A" or x != "C" истинно при любом x: значение не может быть равно сразу A и C, поэтому хотя бы одно неравенство выполнено. «Ни A, ни C» записывают через and: x != "A" and x != "C", или через not и скобки: not (x == "A" or x == "C").

Пример

Ловушка «равно S или W»

В коде IUPAC (страница 09) буквы обозначают и группы нуклеотидов: S значит G или C, W значит A или T, R значит A или G. Программа проверяет, равен ли код S или W. Предскажите вывод обеих строк.

trap_or.py
code = "R"
print(code == "S" or "W")          # → W
print(code == "S" or code == "W")  # → False
Вывод
W
False
  1. Строка 2: левая часть code == "S" ложна, и or отдает правую часть, строку "W". Вместо ответа False программа напечатала букву.
  2. Строка 3: сравнение записано в обеих частях, и ответ верный: код R не равен ни S, ни W.

«Ни TAA, ни TAG»

neither.py
codon = "ATG"
print(codon != "TAA" or codon != "TAG")        # → True
print(codon != "TAA" and codon != "TAG")       # → True
print(not (codon == "TAA" or codon == "TAG"))  # → True
Вывод
True
True
True
  1. Строка 2: условие истинно при любом кодоне, поэтому на ATG ответ верный случайно. Поставьте codon = "TAA": строка 2 по-прежнему даст True, а строки 3–4 дадут False.
  2. Строки 3–4: два правильных способа записать «ни TAA, ни TAG». Они равносильны: not перед скобками превращает == в !=, а or в and.
Практика

Программа должна проверять, равна ли буква G или C, но печатает букву. Исправьте условие и проверьте его на буквах G, C и A.

try_fix.py
base = "A"
print(base == "G" or "C")  # → C
Вывод
C
