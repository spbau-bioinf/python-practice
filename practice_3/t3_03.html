Сокращенное вычисление

20 минутЕрофеев А. И.

Научиться проверять вхождение операторами in и not in с учетом пустой строки и ставить защитную проверку левой частью and, чтобы условие не останавливало программу ошибкой.

1. Проверка вхождения

Теория

Многие проверки последовательности звучат как «есть ли»: есть ли в ней мотив, есть ли неизвестный нуклеотид, входит ли буква в алфавит. Оператор in отвечает на такие вопросы одним выражением, и его удобно соединять с другими условиями.

Оператор in вы видели на странице 03 второй практики: x in s дает True, если строка x входит в строку s как подстрока. Оператор not in дает противоположный ответ: x not in s то же самое, что not (x in s), но читается как фраза.

У in со строками две особенности, о которых легко забыть. Проверяется подстрока, а не одна буква: "CG" in "ACGT" дает True. Пустая строка входит в любую строку: "" in "ACGT" тоже дает True. Поэтому проверка x in "ACGT" пропускает не только буквы алфавита, но и их сочетания, и пустую строку.

Пустая строка появляется в данных чаще, чем кажется: пользователь нажал Enter, не набрав ничего, в таблице не заполнено поле, в файле пустая строка между записями. Функция input() в таком случае возвращает пустую строку "", и ошибки не возникает.

Пример

Что входит в алфавит

Предскажите вывод каждой строки.

membership.py
alphabet = "ACGT"
print("G" in alphabet)      # → True
print("N" not in alphabet)  # → True
print("CG" in alphabet)     # → True
print("" in alphabet)       # → True
Вывод
True
True
True
True
  1. Строка 2: буква G есть в алфавите.
  2. Строка 3: буквы N в алфавите нет, и not in отвечает True.
  3. Строка 4: CG не буква, но такая подстрока в "ACGT" есть.
  4. Строка 5: пустая строка входит в любую строку.

Две записи одного условия

not_in.py
seq = "ATGNNCGT"
print("N" not in seq)    # → False
print(not "N" in seq)    # → False
print(not ("N" in seq))  # → False
Вывод
False
False
False
  1. Строки 2–4 дают одно и то же. Строка 3: in как сравнение связывает сильнее not (страница 02). Строка 4: группировка задана скобками.
  2. Строка 2 читается как фраза «N не в последовательности», и именно ее предлагают программы проверки стиля: pycodestyle выдает на строку 3 предупреждение E713. Руководство PEP 8 также советует писать is not вместо not … is.
Подробнее: in для других типов

Для строк in ищет подстроку. Для списков, кортежей и множеств он проверяет, есть ли среди элементов такой элемент, и [1, 2] in [1, 2, 3] уже ложно. Списки разбираются в теме 5 «Списки и кортежи». Для чисел in не работает: 1 in 123 дает TypeError, потому что число не последовательность.

Практика

Проверьте, есть ли в последовательности TATA-бокс (мотив TATAAA). Затем проверьте строку из одного пробела " ": входит ли она в алфавит?

try_in.py
seq = "GCTATAAAAGGC"
alphabet = "ACGT"
print("N" in seq)      # → False
print("" in alphabet)  # → True
Вывод

True

2. Сокращенное вычисление

Теория

Если первая часть условия с and ложна, вторая уже ничего не изменит: «и» все равно будет ложно. Python этим пользуется и не тратит время на вторую часть. На этом правиле строится защита программы от ошибок.

Сокращенное вычисление — правило, по которому and и or вычисляют правую часть только тогда, когда без нее ответ неизвестен.

Левая часть вычисляется всегда и первой. Если левая часть and ложна, ответ уже False, и правая часть не вычисляется. Если левая часть or истинна, ответ уже True, и правая часть тоже не вычисляется. Правая часть, которая могла бы вызвать ошибку, в этих случаях ошибку не вызывает: до нее просто не доходит очередь.

УсловиеЛевая частьВычисляется ли праваяОтвет
a and bFalseнетFalse
a and bTrueдакак у b
a or bTrueнетTrue
a or bFalseдакак у b
Пример

Правая часть не вычисляется

Деление на ноль останавливает программу ошибкой ZeroDivisionError. Предскажите, остановится ли программа.

short_circuit.py
print(False and 1 / 0 > 1)  # → False
print(True or 1 / 0 > 1)    # → True
Вывод
False
True
  1. Строка 1: левая часть and ложна, ответ известен, деление не выполняется.
  2. Строка 2: левая часть or истинна, ответ тоже известен, и деление снова не выполняется.
Практика

Поменяйте False на True и запустите. Какое сообщение об ошибке появилось? Почему его не было раньше?

try_short.py
print(False and 10 / 0 > 5)  # → False
Вывод

3. Защитное условие

Теория

Пустая строка из ввода, нулевая длина, нулевое число прочтений: такие данные не ошибочны, но на них ломаются обычные операции. Обращение к символу line[0] пустой строки дает IndexError, деление на ноль дает ZeroDivisionError. Сокращенное вычисление позволяет проверить данные и выполнить опасную операцию в одном условии.

Защитное условие (на лекции: безопасная проверка) — проверка, поставленная в условии перед опасной операцией, чтобы до операции не дошла очередь, когда данные для нее не подходят.

Защитное условие ставится левой частью and: line != "" and line[0] == ">". Если строка пустая, левая часть ложна, и обращение к line[0] не выполняется. Порядок частей здесь важен: в записи line[0] == ">" and line != "" левая часть вычисляется первой и останавливает программу раньше, чем очередь дойдет до проверки.

Пример

Начинается ли строка с >

В файле FASTA строка-заголовок начинается со знака >, а между записями бывают пустые строки.

guard.py
line = ""
print(line != "" and line[0] == ">")  # → False
line = ">seq1"
print(line != "" and line[0] == ">")  # → True
Вывод
False
True
  1. Строка 2: строка пустая, левая часть ложна, и line[0] не вычисляется.
  2. Строка 4: строка не пустая, поэтому проверяется и ее первый символ.

Типичная ошибка: защитная проверка справа

Неверно: IndexError
line = ""
print(line[0] == ">" and line != "")
Сообщение об ошибке
Traceback (most recent call last):
  File "guard.py", line 2, in <module>
    print(line[0] == ">" and line != "")
          ~~~~^^^
IndexError: string index out of range
Верно
line = ""
print(line != "" and line[0] == ">")  # → False
Вывод
False

Части and равноправны только в таблице истинности. При вычислении левая часть идет первой, и, если она падает с ошибкой, проверка справа уже не поможет.

Защита от деления на ноль

Доля качественных прочтений считается делением на общее число прочтений, а оно может быть нулем.

reads_guard.py
good = 0
total = 0
print(total > 0 and good / total >= 0.9)  # → False
good = 95
total = 100
print(total > 0 and good / total >= 0.9)  # → True
Вывод
False
True
  1. Строка 3: прочтений нет, левая часть ложна, деление не выполняется, и ответ False: о качестве судить не по чему.
  2. Строка 6: прочтения есть, и доля 0,95 сравнивается с порогом.

Защитных условий может быть несколько подряд, и каждое защищает все, что правее него: x != 0 and y != 0 and 1 / x + 1 / y > 1. Здесь первое условие защищает деление 1 / x, второе деление 1 / y.

Защитное условие подходит и для or, только проверка тогда записывается наоборот: line == "" or line[0] != ">" отвечает на вопрос «это не заголовок?». Если строка пустая, ответ True известен сразу, и line[0] не вычисляется.

Практика

Программа должна проверять, что последний символ строки равен *, но на пустой строке падает. Добавьте защитное условие слева и проверьте программу на строках "" и "MKV*".

try_guard.py
protein = "MKV"
print(protein[-1] == "*")  # → False
Вывод
False

Упражнение 3.3.1. GC-зажим

Что нужно сделать

Праймер лучше связывается с матрицей, если его последний нуклеотид G или C. Дана последовательность праймера, строка может оказаться пустой. Определите, оканчивается ли праймер на G или C. Сначала проверьте, что строка не пустая: это защитное условие.

Входные данные

Одна строка: последовательность из прописных букв A, C, G, T длиной от 0 до 40. При длине 0 строка пустая.

Выходные данные

True, если последний нуклеотид G или C, иначе False. Для пустой строки False.

Упражнение 3.3.1. Нуклеотид в позиции

Что нужно сделать

Чтобы проверить точечную замену, смотрят нуклеотид в заданной позиции. Позиции нумеруются с 1, как в базах данных, а не с 0, как индексы в Python. Даны последовательность, номер позиции и буква. Определите, стоит ли эта буква в этой позиции. Позиция может оказаться за концом последовательности.

Входные данные

В первой строке последовательность из прописных букв A, C, G, T длиной от 1 до 100, во второй целое число p (1 ≤ p ≤ 200), в третьей одна прописная буква A, C, G или T.

Выходные данные

True, если в позиции p стоит заданная буква, иначе False. Если позиции p в последовательности нет, False.

Упражнение 3.3.1. GC-богатый участок

Что нужно сделать

Участок называют GC-богатым, если доля G и C в нем выше порога. Дана последовательность участка, строка может оказаться пустой, и порог в процентах. Определите, GC-богатый ли участок. О пустом участке судить нельзя, он GC-богатым не считается.

Подсказка

Доля считается делением на длину участка. Подумайте, что произойдет с этим делением на пустой строке.

Входные данные

В первой строке последовательность из прописных букв A, C, G, T длиной от 0 до 100, во второй порог: вещественное число от 0 до 100.

Выходные данные

True, если участок непустой и доля G и C в нем в процентах строго больше порога, иначе False.
