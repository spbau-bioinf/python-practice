Вещественные числа

25 минутЕрофеев А. И.

Понять, почему вычисления с float дают погрешность, и научиться сравнивать такие числа с допуском.

Модули. На этой странице нужен модуль math: подключение модулей командой import разобрано на странице 02. Исходные данные в задачах задаются в начале программы, как на странице 06.

1. Почему 0.1 + 0.2 ≠ 0.3

Теория

В CPython на обычных платформах float реализован как 64-битное двоичное число двойной точности по стандарту IEEE 754: около 15–17 значащих десятичных цифр. Большинство десятичных дробей (0,1; 0,2; 1,45) в двоичной записи бесконечны и хранятся приближенно; точно хранятся дроби со знаменателем-степенью двойки, например 0,5 и 0,25.

Целые числа int представляются точно и не ограничены числом разрядов. Но деление / даже целых чисел дает float с его погрешностью.

Аналогия: 1/3 в десятичной записи

Число 1/3 нельзя точно записать десятичной дробью: 0,3; 0,33; 0,333… Сколько цифр ни пиши, точного значения не будет, а если места только на 16 цифр, придется остановиться на приближении.

С двоичной записью происходит то же самое, только неудобными оказываются другие числа. Например, 1/10 в двоичной системе записывается бесконечной периодической дробью 0,000110011…2. Под значащие цифры отведено 53 двоичных разряда, поэтому в памяти хранится ближайшее к 0,1 двоичное число, а не само 0,1.

  • При выводе Python показывает самую короткую десятичную запись, которая однозначно указывает на хранимое число. Поэтому print(0.1) пишет 0.1, хотя в памяти не ровно 0,1.
  • Это свойство формата, а не Python: то же происходит в C, Java, R и в электронных таблицах.
  • Сложение, вычитание, умножение, // и % целых чисел дают точный целый результат.
Пример

Одинаковые с виду выражения

same_looking.py
print(0.1 + 0.1)         # → 0.2
print(0.1 + 0.2)         # → 0.30000000000000004
print(0.1 + 0.2 == 0.3)  # → False
Вывод
0.2
0.30000000000000004
False
  1. Строка 1: погрешности совпали с хранимым 0,2, вывод выглядит точным.
  2. Строка 2: результат оказался соседним двоичным числом, а не тем, что хранится для 0,3.
  3. Строка 3: поэтому сравнение == дает False.

Отсюда правило: вычисленные значения float обычно не сравнивают через ==, если в результате может быть погрешность округления. Для точных значений, например 0.5 + 0.25 == 0.75, == работает.

Что на самом деле хранится

Класс Decimal (страница 08) умеет показать точное значение, которое хранится в float.

stored.py
from decimal import Decimal

print(0.1)           # → 0.1
print(Decimal(0.1))
print(Decimal(0.5))  # → 0.5
Вывод
0.1
0.1000000000000000055511151231257827021181583404541015625
0.5
  1. Строка 3: при обычном выводе Python показывает короткую запись.
  2. Строка 4: Decimal(0.1) переводит хранимое двоичное значение в десятичную запись без потерь: в памяти чуть больше 0,1.
  3. Строка 5: 0,5 = 1/2 хранится точно.

Погрешность накапливается

Десять доз по 0,1 мл складываются в один объем.

ten_doses.py
dose = 0.1
total = dose + dose + dose + dose + dose + dose + dose + dose + dose + dose
print(total)         # → 0.9999999999999999
print(total == 1.0)  # → False
Вывод
0.9999999999999999
False

При каждом сложении результат округляется до ближайшего хранимого числа, и эти маленькие округления складываются. Чем длиннее вычисление, тем заметнее может быть отличие от математического ответа.

Сравнение вещественных чисел через == ненадежно по трем причинам:

  1. ожидаемое значение обычно записано с меньшим числом цифр, чем результат вычисления;
  2. даже перестановка множителей меняет последнюю цифру результата;
  3. округление не спасает: округленные значения тоже приближения.

Три причины в одной программе

not_equal.py
print(5 / 3 == 1.667)  # → False
print(5 / 3 * 0.1)  # → 0.16666666666666669
print(0.1 * 5 / 3)  # → 0.16666666666666666
print(round(0.1, 1) + round(0.1, 1) + round(0.1, 1) == round(0.3, 1))  # → False
Вывод
False
0.16666666666666669
0.16666666666666666
False
  1. Строка 1: 1.667 только запись с тремя знаками, до вычисленного значения ей далеко.
  2. Строки 2–3: математически оба выражения равны 1/6, но разный порядок операций дал разные приближения.
  3. Строка 4: каждое round(0.1, 1) снова приближение к 0,1, и сумма трех таких приближений не совпадает с хранимым 0,3.

2. Сравнение с допуском

Теория

Функция math.isclose(a, b) возвращает True, если числа достаточно близки. У нее два допуска: rel_tol (по умолчанию 1e-09) и abs_tol (по умолчанию 0.0). Числа считаются близкими, если

Условие близости
abs(a - b) <= max(rel_tol * max(abs(a), abs(b)), abs_tol)

rel_tol задает допуск относительно масштаба чисел: при rel_tol=1e-09 разница должна быть не больше 10−9 от большего по модулю числа, а rel_tol=0.05 означает 5 %. Допуск пишется в скобках по имени; такая запись называется именованным аргументом, подробно она разбирается в теме «Функции».

  • Относительный допуск rel_tol задается долей от большего по модулю числа: rel_tol=0.05 означает 5 %. Значение по умолчанию 1e-09 требует совпадения примерно в девяти значащих цифрах.
  • Абсолютный допуск abs_tol задает разницу, которая несущественна сама по себе, независимо от масштаба чисел. По умолчанию он равен нулю.
  • Числа считаются близкими, если разница между ними не больше хотя бы одного из двух допусков.

Какой инструмент выбрать, зависит от вопроса задачи:

СитуацияИнструментЗапись
сравнить два вычисленных числасравнение с допускомmath.isclose(a, b)
отфильтровать по порогусравнение «больше, меньше»gc > 0.4
показать число человекуокругление при выводе, страница 08round(x, 2)
нужен точный десятичный результаткласс Decimal, страница 08Decimal('1.45')
Пример

Сравнение с допуском

isclose.py
import math

print(math.isclose(0.1 + 0.2, 0.3))               # → True
print(math.isclose(1.667, 5 / 3))                 # → False
print(math.isclose(1.667, 5 / 3, rel_tol=0.001))  # → True
Вывод
True
False
True
  1. Строка 3: числа отличаются только погрешностью формата.
  2. Строка 4: 1.667 и 1,6666… отличаются примерно на 0,02 %, это больше допуска по умолчанию.
  3. Строка 5: при допуске 0,1 % они уже близки.

Допуск в процентах

Дозатор должен отмерять 200 мкл с точностью 5 %.

dose_tolerance.py
import math

print(math.isclose(200, 208, rel_tol=0.05))  # → True
print(math.isclose(200, 212, rel_tol=0.05))  # → False
Вывод
True
False
  1. Строка 3: допуск считается от большего числа: 5 % от 208 составляют 10,4, разница 8 допустима.
  2. Строка 4: 5 % от 212 составляют 10,6, а разница 12 больше.
Практика

Подберите наименьший rel_tol из 0.01, 0.001 и 0.0001, при котором 1.667 и 5 / 3 считаются близкими.

3. Сравнение с нулем

Теория

Относительный допуск считается от большего из двух чисел. Если одно из них ноль, допуск получается ничтожным, и math.isclose(x, 0.0) дает False для любого ненулевого x. Для сравнения с нулем задают абсолютный допуск abs_tol.

На числах это выглядит так. Для x = 5,6 · 10⁻¹⁷ относительный допуск по умолчанию равен 10⁻⁹ · 5,6 · 10⁻¹⁷ ≈ 5,6 · 10⁻²⁶, а разница с нулем равна самому x: она в миллиард раз больше допуска.

Точный ноль равен нулю и без допусков: math.isclose(0.0, 0.0) дает True. Это важно, например, для GC-состава, который бывает ровно нулевым.

Как выбрать abs_tol. Абсолютный допуск подбирают по смыслу величины. Для остатков вычислений с долями подходит 1e-9: погрешность формата намного меньше. Для измерений допуск берут из точности прибора: если дозатор отмеряет с шагом 0,1 мкл, разница меньше 0,05 мкл значения не имеет.

Пример

Почти ноль

near_zero.py
import math

residual = 0.1 + 0.2 - 0.3
print(residual)                                   # → 5.551115123125783e-17
print(math.isclose(residual, 0.0))                # → False
print(math.isclose(residual, 0.0, abs_tol=1e-9))  # → True
Вывод
5.551115123125783e-17
False
True
  1. Строка 4: остаток равен примерно 5,6 · 10−17; запись e-17 значит «умножить на 10 в степени −17».
  2. Строка 5: без абсолютного допуска это не ноль.
  3. Строка 6: с abs_tol=1e-9 число считается нулем.
