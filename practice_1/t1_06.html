1. Как считается выражение

Теория

Почти любая обработка данных сводится к вычислениям: длина последовательности в кодонах, число планшетов для партии проб, время прогона, объем реактива. На этой странице арифметика Python разобрана целиком: операторы, два вида деления, остаток и правила, по которым выражение превращается в значение.

Выражение — запись из значений, имен и знаков операций, которую Python вычисляет до одного значения.

Выражение сворачивается по шагам: на каждом шаге выполняется одна операция, и ее операнды заменяются результатом. Какая операция идет первой, задают правила приоритета (раздел 5).

Операнды — значения, над которыми выполняется действие.

Операторы — знаки, которые обозначают действие: +, * и другие.

Выражение 2 + 3 * 4 сворачивается так:

  1. 2 + 3 * 4операнды 2, 3 и 4, операторы + и *
  2. 2 + 12умножение выполняется первым
  3. 14осталось одно значение

Если ошибиться в порядке, Python не сообщит об ошибке: он посчитает другое выражение. Такую ошибку называют семантической, ее выдает только неверный результат.

Пример

Скобки меняют порядок

expressions.py
print(2 + 3 * 4)    # → 14
print((2 + 3) * 4)  # → 20
Вывод
14
20
  1. Строка 1: умножение выполняется раньше сложения: 3 · 4 = 12, затем 2 + 12 = 14.
  2. Строка 2: скобки вычисляются первыми: 2 + 3 = 5, затем 5 · 4 = 20.
  3. Скобки ставят, когда нужен другой порядок или когда порядок должен быть сразу понятен читателю.

Для положительных чисел округление вниз у // совпадает с отбрасыванием дробной части; про отрицательные числа в разделе 3. Степень пишется **: знак ^ в Python означает другую, побитовую операцию, и 2 ^ 3 молча дает 1.

Знак минус перед числом или именем (-x) называется унарным минусом: он меняет знак значения. Вокруг остальных операторов по PEP 8 ставят по одному пробелу: a + b, а не a+b.

В Python 2 деление двух целых чисел отбрасывало дробную часть, и выражение 59 / 60 давало ноль. В Python 3 оператор / всегда делит обычным образом и возвращает float, а для деления нацело есть отдельный оператор //. В старых книгах и на старых сайтах встречается код, который в Python 3 работает иначе.

Операторы // и % отвечают на два вопроса об одном делении:

  • x // y: сколько целых y помещается в x. Сколько полных часов в минутах, полных кодонов в последовательности, полных планшетов в партии.
  • x % y: сколько осталось. Оставшиеся минуты, нуклеотиды, пробы.
  • x % y == 0 проверяет, делится ли x на y нацело; результат True или False.
  • На ноль делить нельзя и здесь: 10 // 0 и 10 % 0 вызывают ZeroDivisionError.

Типичная ошибка: ^ вместо **

Неверно: это не степень
print(2 ^ 3)  # → 1
Вывод
1
Верно
print(2 ** 3)  # → 8
Вывод
8

В электронных таблицах степень обозначают знаком ^, а в Python это побитовая операция, поэтому программа молча выводит 1. Сообщения об ошибке нет, ошибку выдает только неверный результат.

Пример

Два вида деления

division.py
minute = 59
print(minute / 60)    # → 0.9833333333333333
print(minute // 60)   # → 0
print(60 / 60)        # → 1.0
print(type(60 / 60))  # → <class 'float'>
Вывод

<class 'float'>

  2. Строка 3: полных часов в 59 минутах ноль.
  3. Строки 4–5: даже 60 / 60 дает 1.0 типа float.

3. Остаток и отрицательные числа

Теория

Для целых x и y (y ≠ 0) выполняется равенство (x // y) * y + x % y == x: целая часть частного и остаток вместе восстанавливают число.

Поскольку // округляет вниз, для отрицательных чисел результат отличается от отбрасывания дробной части, а остаток получает знак делителя.

Для положительных чисел округление вниз и отбрасывание дробной части совпадают, для отрицательных нет. Функция int() отбрасывает дробную часть: int(-3.5) дает -3, а -7 // 2 дает -4. Остаток получает знак делителя, поэтому при положительном делителе он не бывает отрицательным, и равенство пары по-прежнему выполняется.

Пример

Деление отрицательного числа

negative.py
print(-7 // 2)               # → -4
print(-7 % 2)                # → 1
print(-7 // 2 * 2 + -7 % 2)  # → -7
Вывод
-4
1
-7
  1. Строка 1: −7 / 2 = −3,5, округление вниз дает −4.
  2. Строка 2: остаток −7 − (−4 · 2) = 1.
  3. Строка 3: равенство выполняется: (−4) · 2 + 1 = −7.

Это свойство пригодится для кольцевых координат: позиция на кольцевой плазмиде после сдвига назад остается в диапазоне от 0 до длины.

Кольцевая плазмида

Плазмида длиной 2686 нуклеотидов замкнута в кольцо. Позицию после сдвига назад удобно считать остатком: результат всегда попадает в диапазон от 0 до длины.

plasmid.py
length = 2686
position = 50
shift = 100
print(position - shift)             # → -50
print((position - shift) % length)  # → 2636
Вывод
-50
2636
  1. Строка 4: простое вычитание уводит позицию за начало координат.
  2. Строка 5: остаток от деления на длину возвращает ее на кольцо: −50 − (−1) · 2686 = 2636.

4. Тип результата

Теория

Правило «заражения» (неявное приведение к float): если хотя бы один операнд float, результат тоже float. Деление / дает float всегда.

Если оба операнда int, результат int для +, -, *, //, % и для ** с неотрицательной степенью. Исключений два: деление / всегда возвращает float, возведение в отрицательную степень тоже: 2 ** -1 дает 0.5.

Пример

Один float, и результат вещественный

float_rule.py
print(1 + 2.0)       # → 3.0
print(7 // 2.0)      # → 3.0
print(type(2 ** 3))  # → <class 'int'>
Вывод
3.0
3.0
<class 'int'>
  1. Строка 1: вещественный операнд делает результат вещественным.
  2. Строка 2: даже // с float дает 3.0.
  3. Строка 3: оба операнда целые, результат int.

Один float, и результат вещественный

float_rule.py
print(4 / 2)         # → 2.0
print(1 + 2.0)       # → 3.0
print(7 // 2.0)      # → 3.0
print(7 % 2.5)       # → 2.0
print(2 ** -1)       # → 0.5
print(type(2 ** 3))  # → <class 'int'>
Вывод
2.0
3.0
3.0
2.0
0.5
<class 'int'>
  1. Строка 1: деление / возвращает float, даже если делится нацело.
  2. Строка 2: вещественный операнд делает результат вещественным, хотя значение целое.
  3. Строка 3: целочисленное деление с float дает 3.0, а не 3.
  4. Строка 4: остаток работает и для вещественных чисел: 7 = 2,5 · 2 + 2.
  5. Строка 5: отрицательная степень дает float даже при целых операндах.
  6. Строка 6: оба операнда целые, степень неотрицательная, результат int.

Практическое следствие: длина последовательности, число кодонов и число проб всегда целые. Если такая величина получилась с точкой, значит, в расчете оказалось деление / вместо // или вещественный операнд.

5. Приоритет операций

Теория

Сначала скобки, затем ** (справа налево), унарный минус, потом *, /, //, % (слева направо), потом + и -, в конце сравнения.

ПриоритетОперацииПри равном приоритете
1, высшийскобки ( )изнутри наружу
2степень **справа налево: 2 ** 3 ** 2 = 2⁹
3унарный минус -x
4*, /, //, %слева направо
5+, -слева направо
6, низшийсравнения ==, !=, <, >, <=, >=

Сравнения выполняются после арифметики, поэтому length % 3 == 0 читается как «остаток равен нулю» без дополнительных скобок.

Пример

Ловушки приоритета

precedence.py
print(12 / 2 * 3)   # → 18.0
print(2 ** 3 ** 2)  # → 512
print(-3 ** 2)      # → -9
Вывод
18.0
512
-9
ВыражениеКажетсяНа самом деле
12 / 2 * 312 / (2 · 3) = 2.0(12 / 2) · 3 = 18.0
2 ** 3 ** 28² = 642⁹ = 512
-3 ** 2(−3)² = 9−(3²) = −9

Сомневаетесь в порядке, ставьте скобки. Если скобки повторяют правило, смысл не меняется, а порядок сразу понятен читателю: 2 ** (3 ** 2), (12 / 2) * 3.

Формула из условия в выражение Python

  1. Запишите знаки операций: умножение * (знак не пропускают: 2x пишется 2 * x), деление / или //, степень **.
  2. Числитель и знаменатель дроби, в которых есть сложение или вычитание, возьмите в скобки: (a + b) / c.
  3. Проверьте выражение на простых числах, для которых ответ известен заранее.

Типичная ошибка: забытые скобки в формуле

Относительное изменение в процентах: (новое − старое) / старое · 100. Старое значение 40, новое 50.

Неверно: делится только old
old = 40
new = 50
print(new - old / old * 100)  # → -50.0
Вывод
-50.0
Верно
old = 40
new = 50
print((new - old) / old * 100)  # → 25.0
Вывод
25.0

Без скобок на old делится только old, и из 50 вычитается 100. Рост с 40 до 50 не может дать отрицательный процент: такую ошибку выдает проверка результата на здравый смысл.
