Округление и Decimal

25 минутЕрофеев А. И.

Научиться сравнивать с порогом, округлять значения для вывода и считать десятичные дроби без двоичной погрешности с помощью Decimal.

Как устроены задачи. Функцию input() вы изучите на странице 09, поэтому исходные данные задаются в начале программы строками вида length = 20. Имена переменных берите из условия: проверка подставляет в эти строки свои значения. В поле проверки эти строки уже вставлены.

1. Порог и округление

Теория

Если задача звучит как «GC-состав больше 47 %», допуск не нужен: используйте >, <, >=, <=. Для показа числа человеку используют round(x, n): n знаков после точки.

При точной половине round() округляет к ближайшему четному: round(2.5) дает 2. Число, которое выглядит как половина, может храниться чуть меньше нее: round(2.675, 2) дает 2.67. Округляйте только для вывода.

Погрешность формата при сравнении с порогом играет роль, только когда значение практически совпадает с порогом. Если по условию важна сама граница, решите заранее, куда относится значение, равное порогу, и выберите > или >=.

ВызовЧто получаетсяТип
round(x)ближайшее целое числоint
round(x, n)число с n знаками после точкиfloat, если x типа float
  • При точной половине round() выбирает четное число: round(3.5) дает 4. Такое округление называют банковским: при многократном округлении оно не завышает суммы.
  • Число, которое выглядит как половина, может храниться чуть меньше или чуть больше половины. Значение 2.675 хранится как 2,67499999…, поэтому округляется вниз.
  • Отрицательное n округляет до десятков, сотен и так далее: round(1234.5678, -2) дает 1200.0.
  • Округляйте только при выводе. Округленное значение не делает дальнейшие сравнения надежными (страница 07).
Пример

GC-состав: порог и округление

gc_threshold.py
gc = 596 / 1250 * 100
print(gc)            # → 47.68
print(gc > 47)       # → True
print(round(gc, 1))  # → 47.7
Вывод
47.68
True
47.7
  1. Строка 1: 596 нуклеотидов G и C в последовательности длиной 1250, в процентах.
  2. Строка 3: порог 47 % превышен, сравнение с порогом надежно.
  3. Строка 4: округление только для показа.

Как работает round()

rounding.py
x = 2 / 3
print(round(x, 2))      # → 0.67
print(round(x))         # → 1
print(type(round(x)))   # → <class 'int'>
print(round(2.5))       # → 2
print(round(0.125, 2))  # → 0.12
print(round(2.675, 2))  # → 2.67
Вывод
0.67
1
<class 'int'>
2
0.12
2.67
  1. Строка 2: с числом знаков результат float.
  2. Строки 3–4: без числа знаков результат int.
  3. Строка 5: точная половина 2,5 округлена к четному 2.
  4. Строка 6: 0,125 = 1/8 хранится точно; это точная половина между 0,12 и 0,13, выбрано четное 0,12.
  5. Строка 7: 2,675 хранится чуть меньше половины, поэтому округление вниз.

2. Decimal: десятичные дроби без двоичной погрешности

Теория

Класс Decimal из модуля decimal хранит числа в десятичной системе, поэтому 0,1 или 1,45 в нем представлены точно, без двоичной погрешности float. Результаты операций при этом зависят от контекста точности и правил округления: по умолчанию 28 значащих цифр. Сложение и умножение коротких десятичных дробей укладываются в эту точность и дают точный результат, а, например, Decimal(1) / Decimal(3) округляется.

Число создают из строки: Decimal('1.45'). Decimal складывается с Decimal и с int; смешивать его с float в одной операции нельзя.

Точность Decimal оплачивается скоростью: вычисления с ним медленнее, чем с float. Поэтому его используют там, где точность десятичных дробей принципиальна: в денежных расчетах, дозировках, при сравнении с нормативами. Для измерений, где сами данные приближенные, достаточно float и сравнения с допуском.

  • Подключение: from decimal import Decimal. Эта форма команды import разобрана на странице 02.
  • Число создают из строки. Если создать его из float, например Decimal(1.45), оно унаследует погрешность исходного числа.
  • print() выводит Decimal с тем числом знаков, которое получилось в расчете: у Decimal('2.50') * 3 два знака после точки.
  • Полное имя типа decimal.Decimal: класс Decimal из модуля decimal.
Пример

Десятичная арифметика

decimal_demo.py
from decimal import Decimal

print(Decimal('0.1') + Decimal('0.2'))  # → 0.3
print(Decimal('0.1') + Decimal('0.2') == Decimal('0.3'))  # → True
print(Decimal('2.50') * 3)  # → 7.50
Вывод
0.3
True
7.50
  1. Строки 3–4: сумма точная, и сравнение == здесь надежно.
  2. Строка 5: два знака после точки сохранены.

Деление и точность контекста

decimal_division.py
from decimal import Decimal

print(Decimal('10') / Decimal('4'))          # → 2.5
print(Decimal(1) / Decimal(3))               # → 0.3333333333333333333333333333
print(Decimal('0.1') * 3 == Decimal('0.3'))  # → True
Вывод
2.5
0.3333333333333333333333333333
True
  1. Строка 3: частное записывается конечной десятичной дробью и получено точно.
  2. Строка 4: 1/3 бесконечна и в десятичной записи, поэтому результат округлен до 28 значащих цифр, это точность по умолчанию.
  3. Строка 5: умножение Decimal на целое число точное, и сравнение через == надежно.

Типичная ошибка: Decimal вместе с float

Неверно: TypeError
from decimal import Decimal

print(Decimal('0.1') + 0.2)
Сообщение об ошибке
TypeError: unsupported operand type(s) for +: 'decimal.Decimal' and 'float'
Верно
from decimal import Decimal

print(Decimal('0.1') + Decimal('0.2'))  # → 0.3

Python не смешивает Decimal и float, чтобы погрешность float незаметно не попала в точный расчет. Записывайте исходные данные строками: Decimal('0.2').
