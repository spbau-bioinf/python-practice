Множества

25 минутЕрофеев А. И.

Строить множество функцией set(), выполнять объединение, пересечение и разность, проверять алфавит последовательности подмножеством.

1. Множество и его создание

Теория

Иногда значения словаря не нужны вовсе: важно лишь, какие ключи есть. Чтобы узнать, какие буквы встречаются в последовательности "GATTACA", можно построить словарь-счетчик и взять его ключи, но множество делает то же короче.

Множество (тип set) — неупорядоченная коллекция различных хешируемых объектов.

Функция set() принимает итерируемый объект и строит множество из его элементов; элементы должны быть хешируемыми, поэтому set([[1]]) вызывает TypeError.

Внутри множество устроено как словарь без значений, на той же хеш-таблице (страница 02). Следствия: элементы обязаны быть хешируемыми, проверка вхождения очень быстрая, памяти уходит заметно больше, чем у списка, а порядок элементов ненадежен. Метод add() добавляет элемент, если его нет. Метод discard() удаляет элемент, а отсутствующий элемент молча пропускает; метод remove() в той же ситуации вызвал бы KeyError. Непустое множество можно записать литералом в фигурных скобках: {"A", "T"}. Пустое множество так записать нельзя: пустые скобки {} создают пустой словарь, поэтому пустое множество создают вызовом set().

Пример

Пример 1. Создание множества

bases.py
seq = "GATTACA"
bases = set(seq)
print(len(seq), len(bases))  # → 7 4
print(sorted(bases))         # → ['A', 'C', 'G', 'T']
print("U" in bases)          # → False
bases.add("N")
bases.discard("U")
print(len(bases))            # → 5
Вывод
7 4
['A', 'C', 'G', 'T']
False
5

Из семи букв осталось четыре различные. Множество печатается через sorted(), который возвращает список в алфавитном порядке. add("N") добавляет новый элемент, discard("U") молча пропускает отсутствующий.

Типичная ошибка: пустое множество через {}

Неверно: получился словарь
bases = {}
bases.add("A")
Верно
bases = set()
bases.add("A")

Пустые скобки {} создают пустой словарь, и вызов add() поднимает AttributeError. Пустое множество создают только вызовом set().

Практика

Василиса проверяет буквы последовательности. Замените "GATTACA" на "GATTACAG" и запустите: число разных букв не должно измениться.

2. Операции над множествами

Теория

Множества поддерживают четыре операции из математики, и записываются они знаками. Объединение A | B содержит элементы, которые есть хотя бы в одном множестве; пересечение A & B содержит общие элементы; разность A - B содержит элементы A, которых нет в B; симметрическая разность A ^ B содержит элементы, которые есть ровно в одном из двух. Каждая операция строит новое множество, исходные не меняются.

Если поменять множества местами, результат разности может измениться: при равных множествах обе разности пусты, а в остальных случаях A - B и B - A различаются. Дополнение до известного набора получают той же разностью, например set(range(1, 11)) - A.

У каждой операции есть и метод: union(), intersection(), difference(), symmetric_difference(). Методы принимают аргументом любую коллекцию, по которой можно пройти циклом for, например список или строку, а операторы требуют, чтобы оба операнда были множествами.

Пример

Пример 2. Операции над множествами

sets.py
a = {1, 2, 3, 4, 5}
b = {2, 8, 5, 10}
print(a | b)  # → {1, 2, 3, 4, 5, 8, 10}
print(a & b)  # → {2, 5}
print(a - b)  # → {1, 3, 4}
print(b - a)  # → {8, 10}
print(a ^ b)  # → {1, 3, 4, 8, 10}
Вывод
{1, 2, 3, 4, 5, 8, 10}
{2, 5}
{1, 3, 4}
{8, 10}
{1, 3, 4, 8, 10}

Если поменять множества местами, результат разности может измениться: при равных множествах обе разности пусты, а в остальных случаях a - b и b - a различаются.

Типичная ошибка: оператор со списком

Неверно: список как операнд
a = {1, 2, 3}
print(a | [3, 4])
Верно
a = {1, 2, 3}
print(a.union([3, 4]))  # → {1, 2, 3, 4}

Оператор | требует, чтобы оба операнда были множествами, и со списком поднимает TypeError. Метод union() принимает любую коллекцию, по которой можно пройти циклом.

Практика

Прохор сравнивает наборы. Добавьте строку, которая печатает пересечение a & b, и запустите.

3. Подмножество и проверка алфавита

Теория

Оператор <= для множеств проверяет, является ли первое множество подмножеством второго, то есть входят ли все его элементы во второе. Вопрос «состоит ли строка только из заданных букв» сводится к одной строке: set(строка) <= set(алфавит).

Разность с алфавитом сразу показывает лишние буквы: set(seq) - set("ACGT"). Буква N обозначает неизвестный нуклеотид, поэтому последовательность с буквой N не проходит проверку алфавита.

Тот же результат дает включение множества {b for b in seq if b not in dna}: оно записывается в фигурных скобках, как словарное, но без двоеточия — одно выражение на элемент. Обычное множество изменяемо, поэтому не может быть ключом словаря; неизменяемое множество frozenset хешируемо и годится в ключи. Например, коды неоднозначности нуклеотидов IUPAC обозначают наборы: W означает A или T, S означает C или G, и словарь с ключами frozenset("AT") и frozenset("CG") находит код по паре букв.

Пример

Пример 3. Проверка алфавита

dna.py
dna = set("ACGT")
seq = "GATNACA"
print(set(seq) <= dna)    # → False
print(set(seq) - dna)     # → {'N'}
print(set("GAT") <= dna)  # → True
bad = {b for b in seq if b not in dna}
print(bad)                # → {'N'}
Вывод
False
{'N'}
True
{'N'}

Последовательность содержит букву N, поэтому проверка подмножества дает False, а разность с алфавитом показывает лишнюю букву. Последние две строки делают то же включением множества.

Типичная ошибка: сравнение вместо подмножества

Неверно: равенство
print(set(seq) == dna)
Верно
print(set(seq) <= dna)

Равенство требует, чтобы в строке были все четыре буквы алфавита. Подмножество <= допускает строку, в которой алфавитных букв меньше: главное, чтобы лишних не было.

Практика

Василиса проверяет другую последовательность. Замените "GATNACA" на "GATTACA" и запустите: проверка должна дать True.

dna.py

seq = "GATNACA"
print(set(seq) <= dna)  # → False
Вывод
False
Задача
