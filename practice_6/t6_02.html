Хеширование и ключи

30 минутЕрофеев А. И.

Вычислять ячейку ключа по хешу, прослеживать вставку при коллизии и отличать хеш от шифрования.

1. Хеш и номер ячейки

Теория

Словарь хранит пары «ключ — значение» и находит значение по ключу сразу, не перебирая все пары. Такой поиск возможен потому, что для каждого ключа Python вычисляет число и по нему выбирает ячейку своей таблицы.

Число вычисляет встроенная функция hash(). Для небольших целых чисел хеш равен самому числу: hash(10) дает 10, hash(18) дает 18. Для больших чисел CPython вычисляет хеш с учетом модуля, поэтому равенство hash(n) == n верно не для всех целых; в упражнениях ключи лежат в диапазоне от −1000 до 1000, где оно выполняется. Исключение одно: hash(-1) равно −2, потому что −1 внутри CPython занято служебным значением.

Хеш — целое число, которое хеш-функция вычисляет по объекту. Хеш-функция вычисляет хеш по объекту; в Python это hash().

В учебной таблице номер начальной ячейки равен hash(key) % m. Размер таблицы m равен степени двойки: 8, 16, 32 и так далее.

Разные ключи могут получить один номер ячейки: у 10, 18 и 26 при m = 8 остаток равен 2. Это не ошибка, а коллизия; как словарь ее разрешает, разберем в разделе 3.

Ключом может быть только хешируемый объект: число, строка, кортеж из хешируемых элементов. Список, словарь и множество ключами быть не могут: их содержимое меняется, а хеш ключа должен оставаться прежним.

Пример

Хеш и ячейка

slot.py
for key in (10, 18, 26):
    print(key, hash(key), hash(key) % 8)
Вывод
10 10 2
18 18 2
26 26 2
  1. Для ключа 10 хеш равен 10: hash(10) равно 10.
  2. Остаток от деления на 8 у всех трех хешей равен 2: ключи претендуют на одну ячейку.
  3. Словарь не хранит ключи в порядке номеров ячеек: порядок перебора задает порядок вставки. Об этом ниже.

Типичная ошибка: список вместо ключа

Неверно: список нехешируем
d = {}
d[[1, 2]] = "A"
Сообщение об ошибке
TypeError: cannot use 'list' as a dict key (unhashable type: 'list')
Верно: кортеж хешируем
d = {}
d[(1, 2)] = "A"
print(d[(1, 2)])  # → A
Вывод
A

Список можно изменить после вставки, и его хеш перестал бы соответствовать ячейке. Кортеж из чисел изменить нельзя, поэтому он годится в ключи. В Python 3.12 сообщение короче: TypeError: unhashable type: 'list'.

Хеш строки зависит от всех ее символов, но на настольной 64-битной сборке Python результат всегда укладывается в 64 бита; в браузере страницы работает 32-битная платформа Pyodide, где хеш занимает 32 бита, поэтому в упражнениях размер хеша не используется. В разных запусках hash("ATG") дает разные числа: Python добавляет к строке случайную соль, чтобы хеши нельзя было предсказать заранее. Внутри одного запуска хеш одной и той же строки не меняется, поэтому словарь работает.

Подробнее: кортеж как ключ

Кортеж хешируем, если хешируем каждый его элемент. Хеш кортежа строится из хешей элементов, поэтому у одинаковых кортежей он одинаковый. Кортеж со списком внутри ключом не станет: список нехешируем.

tuple_key.py
point = (3, 4)
d = {point: "A"}
print(d[(3, 4)])  # → A
Вывод
A
Подробнее: почему hash(-1) равно -2

Хеш в CPython на настольной 64-битной сборке хранится в знаковом 64-битном числе Py_hash_t, от −2⁶³ до 2⁶³ − 1. Значение −1 зарезервировано: им внутренние функции сообщают об ошибке. Чтобы настоящий хеш не совпал со служебным, hash(-1) возвращает −2.

Практика

Замените размер таблицы на 16 и запустите. Какие ключи по-прежнему делят ячейку, а какой переехал?

    print(key, hash(key), hash(key) % m)
Вывод

2. Заполнение циклом и размер таблицы

Теория

Когда словарь заполняют циклом for, хеш вычисляется для каждого ключа в момент записи. Длина хеша от длины ключа не зависит: на настольной 64-битной сборке Python хеш занимает 64 бита, то есть 8 байт; в браузере страницы хеш 32-битный. Меняется только значение хеша.

Отдельно хранится размер таблицы m. Он тоже не связан с длиной хеша: m показывает, сколько в таблице ячеек. Функция len(d) возвращает число ключей в словаре, а не длину хеша и не размер таблицы.

"ATGCGTACGT"10 символов8 байт

Пример для CPython при добавлении новых ключей по одному: таблица начинается с 8 ячеек. Когда она заполняется примерно на две трети, Python строит таблицу вдвое больше и переносит в нее все ключи. Сами хеши ключей не меняются, а индексы ячеек рассчитываются заново для нового размера: hash(key) % m зависит от m. Этот перенос называют перехешированием.

sorted при обращении к словарю не нужен: d[key] и key in d находят ключ по хешу, без перебора и без сортировки. Сортируют не словарь, а последовательность ключей или пар, когда нужен предсказуемый порядок вывода.

Сам словарь запоминает порядок вставки: если добавлять ключи G, A, C, перебор даст тот же порядок. Если ключи добавляли в произвольном порядке, вставка его и сохранит. Поэтому в задачах, где важен порядок, результат сортируют.

Пример

Порядок вставки и sorted

ordered.py
counts = {"G": 3, "A": 5, "C": 2}
print(list(counts))    # → ['G', 'A', 'C']
print(sorted(counts))  # → ['A', 'C', 'G']
for key in sorted(counts):
    print(key, counts[key])
Вывод
['G', 'A', 'C']
['A', 'C', 'G']
A 5
C 2
G 3
  1. list(counts) перебирает ключи в порядке вставки: G, A, C.
  2. sorted(counts) строит новый список ключей по алфавиту, сам словарь не меняется.
  3. Цикл по sorted(counts) печатает пары в алфавитном порядке ключей.

Хеш часто путают с шифрованием. Это разные операции: хеш сжимает данные в короткий отпечаток и необратим, шифрование заменяет данные другой записью и обратимо с помощью ключа.

У встроенной функции hash() одно назначение — поиск в словаре и других коллекциях: ее результат стабилен во время жизни объекта. Для воспроизводимой контрольной суммы файла нужен дайджест, например hashlib.sha256. Для хранения паролей применяют специально замедляемые функции hashlib.scrypt, bcrypt или argon2: они медленные, и их результат трудно подобрать.

Подробнее: как устроен хеш в CPython

Хеш малого целого числа равен самому числу, кроме -1, у которого хеш равен -2; для больших целых хеш считается с учетом модуля и совпадать с числом перестает. Хеш строки считается по всем символам и соли, поэтому в разных запусках он разный; соль задает переменная окружения PYTHONHASHSEED. Хеш кортежа комбинирует хеши элементов.

Размер таблицы словаря равен степени двойки, поэтому вместо остатка hash % m CPython берет младшие биты хеша: hash & (m - 1). Для неотрицательного остатка это то же самое, но работает быстрее.

Порядок перебора словаря не совпадает с порядком ячеек. Кроме таблицы ячеек, словарь хранит записи в отдельном массиве в порядке вставки; перебор идет по этому массиву.

Практика

В таблице на 8 ячеек ключи 4, 12 и 20 начинают с одной ячейки. Замените ключи на 6, 14 и 22 и проверьте, в какой ячейке начинается каждый ключ.

try_slots.py
m = 8
for key in (4, 12, 20):
    print(key, hash(key) % m)
Вывод
4 4
12 4
20 4

3. Коллизии и пробы

Теория

Коллизия — случай, когда разные ключи получают одну и ту же начальную ячейку. Хеши при этом могут совпадать или различаться: важно, что совпадает остаток hash(key) % m.

Коллизии неизбежны: ячеек m, а возможных ключей бесконечно много. При m = 8 ключи 10, 18 и 26 все претендуют на ячейку 2.

При вставке проверяется ячейка hash(key) % m. Если она занята другим ключом, проверяется следующая, затем следующая, а после последней проверяется первая. Ключ встает в первую свободную ячейку. Такой способ называют линейным пробированием.

Поиск идет так же: вычислить начальную ячейку, сравнить ключ, при несовпадении перейти к следующей. Совпадение означает, что ключ найден; пустая ячейка означает, что ключа в таблице нет. Поэтому в таблице всегда оставляют свободные ячейки: на пустой поиск останавливается.

Подробнее: пробы в CPython

В учебной модели выше пробы идут в следующую ячейку: 2, 3, 4. В CPython номер следующей ячейки вычисляется по формуле от хеша, поэтому он не всегда больше на единицу. Общее правило сохраняется: ключ занимает свободную ячейку, а поиск останавливается на совпадении или на пустой ячейке. Упражнения практики проверяют учебную модель с шагом 1.

Чем больше таблица заполнена, тем длиннее пробы. При заполнении примерно на две трети словарь растет и перехеширует ключи, как в разделе 2. В среднем вставка и поиск занимают постоянное время, не зависящее от числа ключей; в худшем случае, когда все ключи попали в одну ячейку, поиск перебирает все ключи.

Совпадение хешей не означает равенство ключей. Словарь сравнивает ключи оператором ==: хеш только указывает, где искать. Поэтому разные ключи с одинаковой начальной ячейкой остаются разными ключами: путь проб идет по соседним ячейкам, а занятые позиции разных ключей могут оказаться дальше друг от друга.

Пример

Поиск при коллизии

lookup.py
d = {10: "A", 18: "C", 26: "G"}
print(d[18])             # → C

Вывод
C
True False
  1. Все три ключа при m = 8 начинают с ячейки 2, но словарь различает их по значению ключа.
  2. d[18] находит значение C: словарь проверяет ключи, пока не встретит равный.
  3. 15 в словаре нет: поиск доходит до пустой ячейки и сообщает, что ключа нет.

  1. Храните занятость ячеек в списке table из m элементов. Чтобы не вставлять повторный ключ, запоминайте готовый ответ в словаре slot_of. Номер следующей ячейки: (slot + 1) % m; после последней ячейки счет возвращается к нулю.
