Хеширование и ключи

30 минутЕрофеев А. И.

Прослеживать, как словарь находит ключ по хешу, и составлять ключ из нескольких значений кортежем.

1. Как словарь находит ключ

Теория

На странице 01 сказано, что словарь находит значение по ключу сразу, а не перебором. Оператор in у списка проверяет элементы по одному. В списке из миллиона названий нужное может оказаться последним, и тогда понадобится миллион сравнений. Словарю столько сравнений не нужно.

Словарь не перебирает ключи. По ключу он вычисляет число и по этому числу сразу идет к нужному месту своей таблицы.

Хеш (hash) получается из значения объекта: это целое число, которое вычисляет функция hash(). Например, hash(10) дает 10. Равные значения всегда дают равные хеши.

Таблица словаря состоит из пронумерованных ячеек. В учебной модели этой страницы ключ кладут в ячейку с номером hash(key) % size, где size означает число ячеек. Остаток от деления на 8 лежит от 0 до 7, поэтому в таблице из 8 ячеек номер всегда существует. У небольших целых чисел хеш равен самому числу: ключ 10 попадает в ячейку 10 % 8, то есть 2, а ключ 13 в ячейку 5.

Ячейка может оказаться занятой: ключ 18 тоже дает 18 % 8, то есть 2, а в ячейке 2 уже лежит ключ 10.

Коллизия (collision) возникает, когда разные ключи получают одну и ту же начальную ячейку.

При коллизии новый ключ проверяет следующую ячейку, потом еще одну, пока не найдет свободную; после последней ячейки проверяется ячейка 0. Поиск идет тем же путем. Он начинает с ячейки hash(key) % size и сравнивает ключи оператором ==. Встретился равный ключ, значит, ключ найден. Встретилась пустая ячейка, значит, такого ключа в словаре нет.

Поиск останавливается на пустой ячейке, поэтому таблицу словаря никогда не заполняют целиком: когда занято примерно две трети ячеек, Python строит таблицу больше.

Таблица ниже показывает вставку пяти ключей в таблицу из 8 ячеек по этому правилу. Ключи 10, 18 и 26 начинают с ячейки 2 и встают в ячейки 2, 3 и 4. Ключ 13 начинает с ячейки 5, но ее уже занял ключ 5, поэтому 13 встает в ячейку 6.

Учебная модель упрощена. В CPython таблица словаря сначала содержит 8 ячеек и увеличивается, когда занято около двух третей; следующая ячейка при коллизии вычисляется формулой от хеша, а не прибавлением единицы. Хеш строки зависит от случайной «соли», которую Python выбирает при каждом запуске: в разных запусках hash("ATG") разный, внутри одного запуска одинаковый. Из небольших целых чисел особое только −1: hash(-1) равно −2, потому что −1 внутри CPython означает ошибку.

Пример

Пример 1. Хеш и начальная ячейка

cells.py
for key in (10, 18, 5):
    print(key, hash(key), hash(key) % 8)
Вывод
10 10 2
18 18 2
5 5 5

Хеш каждого ключа равен самому ключу. Ключи 10 и 18 в таблице из 8 ячеек получают одну начальную ячейку 2 — это коллизия; ключ 5 начинает с ячейки 5.

Пример 2. Поиск при коллизии

lookup.py
d = {10: "A", 18: "C", 26: "G"}
print(d[18])             # → C
print(10 in d, 15 in d)  # → True False
Вывод
C
True False

Все три ключа начинают с ячейки 2, но словарь различает их сравнением: d[18] находит свое значение. Ключа 15 нет: его поиск остановился на пустой ячейке.

Практика

Замените 8 на 16 и запустите: теперь все три ключа начинают с разных ячеек (10, 2 и 5).

cells.py
for key in (10, 18, 5):
    print(key, hash(key) % 8)
Вывод
10 2
18 2
5 5

2. Что может быть ключом

Теория

Можно ли сделать ключом любой объект, например список? Вспомним, как словарь работает. Он вычисляет хеш ключа один раз, при записи, и кладет ключ в ячейку по этому хешу. Если бы ключ потом изменился, изменился бы и хеш. Словарь стал бы искать ключ не в той ячейке и не нашел бы его.

Хешируемый объект (hashable) имеет хеш, который не меняется, пока объект существует. Ключом словаря может быть только хешируемый объект.

Числа, строки и None изменить нельзя, поэтому они хешируемы. Кортеж тоже нельзя изменить, и он хешируем, если хешируемы его элементы. Список, словарь и множество можно менять, поэтому они нехешируемы: d[["A", "T"]] = 1 останавливает программу ошибкой TypeError: unhashable type: 'list'.

Кортеж нужен, когда место задают несколько значений сразу. Например, место замены нуклеотида задают номер хромосомы и позиция в ней. Ключом делают кортеж из двух чисел: mutations[(17, 41245466)]. Скобки внутри квадратных можно не писать, mutations[17, 41245466] означает тот же кортеж.

Ключи словарь сравнивает по значению. Числа 1, 1.0 и True равны, поэтому для словаря это один и тот же ключ: после d[1] = "a" и d[1.0] = "b" в словаре одна пара, и ключом остается первый записанный, целое число 1.

Кортеж хешируем, только если хешируемы все его элементы: (17, [100, 200]) ключом быть не может, потому что внутри список. Множество, как и список, можно менять, но у него есть неизменяемый вариант frozenset, и он годится в ключи. Множества разбираются на странице 05.

Пример

Пример 3. Кортеж как ключ и равные числа

keys.py
mutations = {(17, 41245466): "G", (13, 32906729): "T"}
print(mutations[17, 41245466])  # → G
print((13, 100) in mutations)   # → False
values = {}
values[1] = "целое"
values[1.0] = "вещественное"
print(values)                   # → {1: 'вещественное'}
Вывод
G
False
{1: 'вещественное'}

Ключ — пара «хромосома, позиция». Запрос (13, 100) отличается от ключа (13, 32906729) позицией, поэтому in дает False. Ключи 1 и 1.0 равны: вторая запись заменила значение, а ключом осталась целая единица.

Типичная ошибка: список вместо ключа

Неверно: список как ключ
d = {}
d[["A", "T"]] = 1
Верно
d = {}
d[("A", "T")] = 1

Список можно изменить после вставки, поэтому ключом он быть не может: программа останавливается ошибкой TypeError: unhashable type: 'list' (в Python 3.14 сообщение длиннее, но тип ошибки тот же). Кортеж изменить нельзя, он годится в ключи.

Практика

Добавьте в словарь пару (13, 100): "A" и запустите: вторая строка вывода должна стать True.

keys.py
mutations = {(17, 41245466): "G", (13, 32906729): "T"}
print(mutations[17, 41245466])  # → G
print((13, 100) in mutations)   # → False
Вывод
G
False

Контекст

Место замены в геноме человека задают две величины: номер хромосомы и позиция в ней. Одна и та же позиция есть в каждой хромосоме, поэтому ключом служит пара чисел, а не одно число.

Основные определения

  • Геном — вся ДНК организма.
  • Хромосома — одна из молекул ДНК, на которые разделен геном; у человека 22 пары обычных хромосом, их обозначают номерами.

  • Образец — биологический материал, последовательность которого прочитали; у образца есть название.
  • Кортеж-ключ — пара значений в круглых скобках, например (17, 100); кортеж не меняется, поэтому годится в ключи.

  2. Ключом сделайте кортеж из двух чисел: (int(chromosome), int(position)), а значением букву. Номера прочитаны строками, поэтому их переводят функцией int().

Условие задачи

Задача со звездочкой 6.2. Таблица после вставки

Условие задачи

Вставьте ключи в таблицу из size ячеек в порядке ввода по правилу из раздела 1. Начальная ячейка ключа равна hash(key) % size. Если она занята, проверяется следующая, а после последней ячейки проверяется ячейка 0. Выведите содержимое ячеек по порядку: ключ или знак _, если ячейка пустая.

Входные данные

В первой строке число ячеек size: 4, 8, 16, 32 или 64. Во второй строке от 1 до size различных целых ключей от 0 до 1000 через пробел.

Ключи 3, 11 и 19 начинают с ячейки 3. Первый ключ ее занимает, второй уходит в ячейку 4, третий в ячейку 5.

Основные определения

  • Хеш-таблица — ряд пронумерованных ячеек; ключ кладется в ячейку с номером hash(key) % size.
  • Функция hash() — вычисляет по значению целое число, хеш; равные значения дают равные хеши.
  • Остаток % — hash(key) % size дает номер ячейки: целое число от 0, меньшее size.
  • Коллизия — два ключа претендуют на одну начальную ячейку.
  • Переход по кругу — (slot + 1) % size после последней ячейки дает 0.
Подсказка
  1. Храните таблицу списком из size элементов None: table = [None] * size.
  2. Для каждого ключа начните с ячейки hash(key) % size и, пока ячейка занята, переходите к следующей: slot = (slot + 1) % size.
  3. Положите ключ в найденную свободную ячейку.
  4. Соберите вывод: вместо None знак _, вместо ключа его запись строкой.
  5. Сверьтесь с примером: для ввода 8, 3 11 19 программа печатает _ _ _ 3 11 19 _ _.

Задача со звездочкой 6.2. Пробы при вставке

Условие задачи

Вставьте ключи в таблицу из size ячеек в порядке ввода по правилу из раздела 1. Начальная ячейка ключа равна hash(key) % size. Если она занята, проверяется следующая, а после последней ячейки проверяется ячейка 0. Каждая проверка занятой ячейки при вставке нового ключа считается одной пробой. Ключ, который уже вставлен, второй раз не вставляется и проб не дает. Задача со звездочкой 6.2. Сколько ячеек проверит поиск

Условие задачи

Вставьте ключи в таблицу из size ячеек в порядке ввода по правилу из раздела 1. Начальная ячейка ключа равна hash(key) % size. Если она занята, проверяется следующая, а после последней ячейки проверяется ячейка 0. Затем ответьте на запросы: сколько ячеек проверит поиск ключа. Поиск начинает с ячейки hash(key) % size и идет по кругу до ячейки с этим ключом или до первой пустой ячейки; первая проверенная ячейка тоже считается. Если ключа в таблице нет, выведите -1.

Входные данные

В первой строке число ячеек size: 4, 8, 16, 32 или 64. Во второй строке от 1 до 20 различных целых ключей от 0 до 1000 через пробел; в таблице остается хотя бы одна пустая ячейка. В третьей строке от 1 до 20 ключей-запросов от 0 до 1000.
